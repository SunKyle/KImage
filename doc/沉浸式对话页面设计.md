# 沉浸式对话页面设计

> 一份"把工具那一层收走、把画面还给角色"的设计。
> 它是 [角色对话功能设计.md](角色对话功能设计.md) 的**第二种骨架**，不是第二个页面；
> 上游那份讲"对话本身怎么像人"，这一份讲"这一页怎么不像软件"。
> 破功清单的判据沿用 [对话沉浸感设计.md](对话沉浸感设计.md)。
>
> **已定的四件事**（2026-10-05，用户拍板，动手前不要再来回）：
> ① 沉浸态**不留换人**；② 背景用**角色正脸**；
> ③ 头部**常驻**（不做滚动淡出）；④ **不做**浏览器返回键退出。

---

## 0. 先把词定死

普通页回答的是**"我在用一个软件，跟一个角色聊天"** —— 所以它有左栏、模型药丸、
记忆入口、`⋮` 菜单。沉浸页只回答一件事：**"我在跟它说话。"**

于是判据只有一条：

> **屏幕上每一样东西，是在服务这段话，还是在服务"这个软件的功能"？**

后者全部收走。但有一个例外：**出错、撤销、正在生成**这些"此刻正在发生的事"
不能跟着一起收 —— 藏掉它们，沉浸就变成了陷阱（§6）。

---

## 1. 前提：同一页的第二种骨架，不是第二个页面

| 决定 | 为什么 |
| --- | --- |
| **状态、消息、输入、流式全复用**，只换外层 chrome | "再写一个对话页"的最后一定是两块逻辑互相漂移。这个仓库已经吃过两次：`trapTab` ×3、`v-grow` ×2（见 [优化计划.md](优化计划.md) 的 T2.1 / T10.5） |
| **消息流是同一棵 DOM**，只改外层容器与 class | 不只是省事：`role="log"` 的 live region **只在它自己身上生效**（§10.1）。切模式时若把消息流整棵重造，读屏会把整段对话重新播报一遍 |
| 实现形状：一个 `immersive` 状态 → 外壳一个 class → ChatPage 一个 prop | 不用新的 store、不用新的路由、不用第二份 props |

## 2. 减 / 加 / 守

### 2.1 减（工具层，全部收走）

| 收走 | 为什么 |
| --- | --- |
| 顶栏（品牌 / 导航 / 主题开关） | 它是"站"的存在感。**但它是回别的页的唯一入口**，所以退出的门必须放大（§5） |
| 左栏角色列表 | 换人是"离开这段对话"，该有一点代价（已定：不留） |
| 头部的 Model / Memory 两枚药丸 | 它们回答"它是怎么接的线"，不回答"它是谁" |
| `.chat-main` 的边框与底色 | 面板感就是工具感。对话该**浮在场景上**，不是装在框里 |
| `⋮` 菜单（清空 / 编辑记忆 / 忘记） | 维护动作。退出一次很便宜，常驻很贵 |

### 2.2 加（把画面还给角色）

| 加 | 为什么 |
| --- | --- |
| 它的正脸铺满背景 | 屏幕最大的那块面积归它，而不是归留白 |
| 居中一列（`--immersive-col: 760px`） | 阅读宽度；两侧交给背景，不再是空白 |
| 字号上一档（正文 15–16px） | 这一页只有对话，没有别的东西抢层级 |
| 更松的行距与气泡间距 | 呼吸感来自"没有别的信息要挤"，不是来自装饰 |
| 极简头部：头像 · 名字 · mood · 退出 | 只留"我在跟谁说话"这一个事实 |

### 2.3 守（**这一层不能跟着"沉浸"一起藏掉**）

`notice` / 错误提示 / 撤销条 / "回到最新 N new" / 流式光标 / 情绪药丸 /
时间分隔 / "Last spoke 3 days ago" / 每条消息的朗读键 / 生成中的 Stop。

> 一句话：**沉浸不是"看不见工具"，是"看不见不需要的工具"。**

## 3. 骨架

```
┌──────────────────────────────────────────────────┐
│ [头像] 名字 · mood                     [◱ 收起]   │ ← 头部：常驻、极简
├──────────────────────────────────────────────────┤
│                                                  │
│        ┌──────────────────────────┐              │
│        │                          │              │
│   角色正脸：铺满 + 压暗 + 上下羽化    │  消息流       │ ← 两侧不再是空白，
│        │      （居中一列 760）      │              │   而是"它在的地方"
│        │                          │              │
│        └──────────────────────────┘              │
│                                                  │
├──────────────────────────────────────────────────┤
│        ┌──────────────────────────┐              │
│        │  输入区（悬浮卡片）        │              │
│        └──────────────────────────┘              │
└──────────────────────────────────────────────────┘
```

### 3.1 一条旧决定要在这里翻案（必须写清楚，否则下一个人以为漏了）

普通页明确否掉了"收在中间 760px 一列"，理由是
"这块面板只有一个说话对象，两侧再空出两百多像素看着就是没铺满"
（[角色对话功能设计.md](角色对话功能设计.md) §3.4.4）。

**沉浸页该收窄，因为前提变了**：普通页那两侧是**面板内部的留白**（纯灰底，所以显得空）；
沉浸页那两侧是**角色的画面**。

> 同一个决定在两个骨架下答案相反 —— 不是自相矛盾，是条件不同。

### 3.3 剧本那套（2026-10-05 · 参考图定下的方向）

用户给了一张参考图（companion.app 的一屏），要求按那个来。那张图不是"聊天界面"，
是**一页剧本压在剧照上**。它的构成拆开是七条：锐利剧照铺满；没有气泡与头像，
**靠字体音区认人**（角色：大、亮、衬线；你：小、暗、同一衬线族）；旁白斜体一行；
头部居中"名字 + 场景 · 时间"；正文是**短窗渐隐**而不是消息流；输入是一条宽胶囊；
底部一行环境字幕。

| 参考里的 | 我们怎么办 |
| --- | --- |
| 两个声音、没有气泡 | ✅ 已落：同一棵 DOM，沉浸态把气泡的**底与边一起收掉**、左对齐、按 `role` 分两档字号与明度（`.chat.is-immersive` 那一段） |
| 名字 + 场景 · 时间 | ✅ 已落：场景取自**它自己最后一条照片意图写的描述**（`reply.photo`），时间读本机钟 —— 两样都不新增调用 |
| 衬线台词 | ✅ 已落：新增 `--font-serif`（各端系统衬线，零加载），**全站只有沉浸页的台词用它** |
| 短窗渐隐 | ✅ 落成 `mask-image` 上渐隐 + 收掉流内的时间分隔（末尾那条 "Last spoke" 留着，它答的是"多久没见"） |
| 输入宽胶囊 | ✅ 落成 `.compose-box` 圆角 999 + 提示语改成 `Tell {name} something…` |
| 环境字幕（`Rain outside`） | ❌ 不做：它和"旁白"只隔一层纸，而旁白**已经定了不做** |
| 旁白（`she looks away for a moment`） | ❌ **不做**（2026-10-05 用户定）。它与 `CHAT_RULES` 里"No narration, no stage directions"那条正面冲突，要做就得开一条显式标签通道 —— 决定不开 |
| 麦克风 | ❌ 不做（语音输入仍是"先放着"，§8.4） |

> **两处只有截图才发现的错**（都记在这儿，免得再犯）：
> ① 沉浸态的覆盖规则原来写在样式表**中间**，而 `.msg.assistant .bubble` 在它后面 ——
> 同等特异度比先后，于是气泡底色照旧漏出来，每句台词顶着一块浅灰方块。
> 覆盖层**必须放整个样式表的最后**。
> ② 收了底色但没收 `border`，每句台词还被一圈细线框着 —— 那圈的底与边是**一起给的**（见那条规则的注释）。

### 3.2 高度

沿用普通页那套：整页钉死、**只有消息流内部滚**。
`.chat` 的算式里减掉顶栏那一项（`--mast-h`）在沉浸态会**自动变成 0**（见 §6.2），
所以这条算式**一个字都不用改**。

## 4. 背景层：用它已有的正脸

`coverSrc(c.ref)` 就是它的正脸（[ChatPage.vue](../src/components/ChatPage.vue) 的 `avatarOf`），
**字节已经在内存里** —— 不加请求、不加调用、不加钱。

| 正脸（`ref`） | 只有底图（`sourceRef`） | 两个都没有 / 加载失败 |
| --- | --- | --- |
| 铺满 + 压暗 + 轻微虚化 + 上下渐变蒙版 | 同上，用底图 | 主题色 + 极淡的纸纹（复用 `bg-light/dark.webp`），**静默退化** |

> **2026-10-05 补的那条退路**：原来只认正脸，而"只上传过一张图、还没生成过正脸"
> 是一种很常见的角色 —— 那种角色切进沉浸页就是一片空的压暗色（用户的原话是
> "没有背景图啊"）。现在退到 `sourceRef`（上传的那张底图）：它同样是"它长什么样"，
> 有它也比只剩一层色强。两个都没有才落到主题色。

两条硬约束：

1. **对比度是硬约束，不是审美**：正文在最弱那一档背景下也要满足小字可读
   （约 4.6:1，见 [整体设计风格.md](整体设计风格.md) §八）。压暗那一层就是为它存在的。
2. **别拿原图去 blur**。

> **2026-10-05 实测修正**：原稿写的是"正脸可能上千像素，先降到 1080 再 blur"。
> 实际存下来的那张是 `CHAR_IMAGE_MAX`（1280）的 JPEG（见
> [useCharacters.ts](../src/composables/useCharacters.ts) 的 `charImageBlob`）——
> 降到 1080 几乎是个空操作，不值得为它加一段 canvas 代码。所以**没做降采样**，
> 改成两件更省的事：压暗蒙版把画面盖掉一半、窄屏把 blur 从 34px 收到 22px。
>
> 蒙版的形状也是按"**压在背景上的那几行字在哪**"定的，不是随手一个渐变：
> 上重（角色名）、中轻（那一带基本被气泡盖着，让出画面）、下重（输入区那块提示）。
>
> **2026-10-05 第三次调（用户："和我给的第二张参考图完全不一样"）**：
> 差距的根子在**第一版用大虚化换可读性**——参考图里那张照片是**锐利**的，
> 而虚化把"这一场戏"整个糊没了，那一页的全部意思也就没了。
> 改成参考图的做法：**画面锐利（blur 2px）+ 靠蒙版让位**——
> 横向一道（左边重、右边接近透明）给文字，纵向两道给角色名与输入区；
> 同时**正文改成靠左**（参考图里字在左、人在右，那个不对称就是它的构图），
> 输入区仍居中；场景行收成**第一小句**（`a grey window at dawn · 11:43`，
> 不再是那整段出图提示词）；流内的图再收小一档。
>
> **还差一条，得先问**：参考图那张照片是**构图给文字让了位**的（人在右、左边是暗的），
> 而我们生成的剧照通常把人放在正中，左边那道蒙版会横着压在人身上。
> 要真做像，得给出图那一段加一条构图约束（"主体靠右、左侧留出暗部"）——
> 那会改掉**所有**生成的剧照，所以先不动，等决定。
>
> **2026-10-05 第二次调**：第一版（图 0.55 / 蒙版 78-58-62-82）在真机上"看不出有背景" ——
> 用户按判据查过，`document.querySelector('.chat-bg img').src` 是有值的：**图在，只是被盖没了**。
> 现在调到图 0.72 / 蒙版 70-42-46-74，深浅两个主题下那张脸都清楚可辨，而气泡是不透明的，
> 所以读字一点没受影响。
>
> **代价说清楚**：背景一亮，压在它上面的那几行**小字**就更难读了 ——
> `.sep`、`Last spoke 3 days ago`、`Couldn't generate that image.`、
> 输入区那句提示，用的都是 `--text-4`（浅色 1.65:1 / 深色 2.01:1）。
> 它们**本来就低于项目自己定的 4.6:1**，只是从前背景几乎是一片纯色才没暴露。
> 所以"把背景调亮"和"把这档灰提一档"是一对，不能只做前一半。

**背景层的实测取法**：`.chat-bg` 固定定位铺满视口（它不该被 `.shell` 的栏宽与
内边距裁住），`z-index: 0`，两层网格子项各自 `position: relative; z-index: 1`
—— 不用负 z-index（那会跑到 body 背景之下，效果随浏览器的绘制顺序而变）。

## 5. 进出

| 问题 | 决定 | 为什么 |
| --- | --- | --- |
| 入口 | 对话页头部最右一枚"展开"（与 `⋮` 同一排） | 与它要去的地方同一排，肌肉记忆连续 |
| 出口 | **两处**：同位置的"收起"、`Esc`（窄屏同一枚按钮） | 一个藏起出口的全屏模式就是把用户关在里面 |
| `Esc` 的层级 | 菜单 → 角色浮层 → **最后才是退出沉浸** | 接进既有的 `layerOnEscape`（[lib/ui.ts](../src/lib/ui.ts)），沉浸模式是最外面那一层 |
| Fullscreen API | **不用** | `Esc` 的语义会跟浏览器打架，iOS Safari 对非视频元素基本没有；它还会把"沉浸"变成一次权限弹窗。**填满视口就够了** |
| 浏览器返回键 | **不做**（已定） | 这个站没有路由（[优化计划.md](优化计划.md) 里"无路由深链"还挂着），返回键会直接把用户带离整个应用。想让它也能退得手动 `pushState` —— 脏，且不该是主要出口 |
| 焦点 | 进来交给输入框，出去还给那枚按钮 | 你进来是为了说话；焦点掉在文档开头是这家仓库一直在修的那类问题 |
| 记住偏好 | `kimage.immersive` 存本地，**默认关** | 存量用户不该被突然换一套骨架；记住之后下次进对话页直接是沉浸 |
| 离开对话页 | 偏好不动，**这一页的 chrome 回到普通** | 顶栏必须回来 —— 它是去别的页的唯一入口 |

## 6. 六个会打架的地方（真正动手时才会撞上）

### 6.1 撤销条 vs 输入区 —— 量过了，确实打架，已修

`UndoToast` 是 `bottom: 28px` 固定居中（[UndoToast.vue](../src/components/UndoToast.vue)），
而聊天页的输入卡片也是**底部居中**。

**实测（1280×900，探针量的）**：撤销条 `828–872`，输入卡片 `811–859`，
**重叠 31px** —— 而且它不只难看：那一块**会吃掉点击**，想点进输入框打字的那一下
会落在撤销键上，把刚删掉的东西又撤销回来。这是"看一眼才知道"的典型：
从代码上看两条都合理，只有量出来才发现它们占了同一块地方。

**修法**：`.undo.over-compose { bottom: 100px }`，类名由主界面按
"当前是不是对话页"给（`page === 'chat'`）。值 = 输入卡片顶边到视口底的距离
（约 92px）+ 一道缝。修完实测 `overlap: 0`。

普通页其实也有同样的重叠（两条的几何一样）—— 这条修复顺带把它一起解决了，
因为它挂的是"在对话页"而不是"在沉浸态"。

### 6.2 `--mast-h` 与高度算式（免费的一处，但有个坑）

顶栏用 **`v-show`** 藏掉时 `offsetHeight` 变 0，`mastRO` 会把 `--mast-h` 写成 `0px` ——
**这一处不用额外改**。

**但不能用 `v-if` 卸载顶栏**。

> **2026-10-05 实测修正（原来的预判说错了一半）**：换成 `v-if` 之后，坏的**不是沉浸页
> 而是普通页**。元素被移除时 `ResizeObserver` 会**报一次 0 尺寸**，所以 `--mast-h`
> 在沉浸态照样是 `0px`（看上去是对的）；真正坏掉的是**重新挂载那一次** ——
> 观察者还挂在已经被摘掉的旧节点上，`--mast-h` 于是**永远停在 0**，
> 而顶栏明明有 72px 高。症状是"普通页的面板高出 72px"。
>
> 所以判别性检验落在**基线**那一条上：`mastVisible` 为真时 `--mast-h` 必须非零
> （已实测变红）。这个坑依然安静 —— 功能全对，只是差 72 像素。

### 6.3 `role="log"` 的 live region

两个骨架**必须共用同一个消息流节点**。若沉浸态用 `v-if` 另造一棵树，
切模式时读屏会把整段对话重新播报一遍。**这一条直接决定实现形状**：
改外层容器与 class，不改消息流本身。

### 6.4 隐藏左栏之后，那条 `240px` 的轨道还在

`.chat` 是 `grid-template-columns: 240px minmax(0, 1fr)`。
把左栏 `display: none` **不会**让那一列塌掉 —— 显式的轨道宽度还在，
右边会平白少 240px 再加一道 `gap`。

沉浸态必须显式改 `grid-template-columns: minmax(0, 1fr)`。
这是 CSS Grid 的常规行为，但它的症状是"右边窄了一截"，很容易被当成 padding 问题。

### 6.5 `.shell-wide` 的 `overflow`

保持 `clip`（**不是 `hidden`**）：`hidden` 会让 `.shell` 变成滚动容器，
聚焦底部输入框时浏览器可能把它滚一下（见 [角色对话功能设计.md](角色对话功能设计.md) §10.7）。

### 6.6 窄屏与减少动效

- `100dvh` + `env(safe-area-inset-bottom)`；键盘弹出时 `dvh` 会缩，消息流继续贴底；
- 进/出只做**透明度**，不做缩放位移（`prefers-reduced-motion`）。

## 7. 不做的事

| 不做 | 为什么 |
| --- | --- |
| 自动放音乐 / 打字音效 / 呼吸光晕 | 那是**表演**沉浸。而且"自动出声"这个站已经否过一次（§8.4 删掉自动朗读） |
| 背景现画一张 AI 图 | 每次进入都花钱；它已有的正脸就是本人 |
| 第二套消息渲染 | 两份实现必然漂移，还会毁掉 §6.3 那条 live region |
| 把错误也"沉浸"掉 | 出错时用户最需要确切信息；用氛围盖住事实是欺骗（[对话沉浸感设计.md](对话沉浸感设计.md) §3.4.2） |
| 把沉浸做成默认 | 默认值是最强的产品表达。存量用户没要求过这个，别替他决定 |

## 8. 验收口径

沉浸感不能直接测，但**这几件可以**：

| 类型 | 判据 | 怎么取 | 状态 |
| --- | --- | --- | --- |
| 骨架真的换了 | 顶栏不可见、`--mast-h` 为 0、左栏不在布局里、单列 | 浏览器探针 | ✅ 已接 |
| 骨架换来的是**高度** | 沉浸态面板高 = 普通态 + 顶栏那 72px | 浏览器探针（比在视口高度上做文章稳：后者会被 `min-height` 盖过） | ✅ 已接 |
| 两个骨架没有漂移 | 消息流是**同一棵 DOM**：切模式前后给节点盖的戳还在 | 探针（`__probeStamp`） | ✅ 已接 |
| 背景层 | 沉浸态有 `.chat-bg img`（blob URL）、普通态没有；没有正脸时退化成压暗色 | 探针 | ✅ 已接 |
| 工具层与出口 | 药丸 / `⋮` / 可点换人入口收起；身份留下；**收起按钮在** | 探针 | ✅ 已接 |
| 破功没跟着藏 | 撤销条 / "回到最新"在沉浸态仍然可见可点；撤销条**不压输入区** | 探针（含重叠像素数） | ✅ 已接 |
| 整页仍钉死 | `.shell` 的 `overflow` 仍是 `clip` | 探针 | ✅ 已接 |
| 对比度 | 两种主题下正文与背景 ≥ 4.6:1 | **仍没有自动判据**：背景是图片，取不到"计算样式里的背景色"。现在的替代是**两种主题各拍一张**（`measure-history.mjs --shot-dir`，会连拍深色与浅色），用眼睛过一遍 | ⚠️ 半自动 |
| 读屏不重播 | live region 没被重建 | 探针已覆盖"节点身份"，但**读屏本身没有测** | ⚠️ 半 |
| 焦点 | 进来落在输入框、出去回到那枚按钮 | 手测（探针没有测） | ⚠️ 手测 |
| 记住偏好 | 偏好存本地；**在首页时不该沉浸**（顶栏是全站唯一出口） | 探针 | ✅ 已接 |
